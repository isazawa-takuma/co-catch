# コキャッチ E2Eテスト観点・テストケース

## 1. 目的

本ドキュメントは、コキャッチ（オペナビ顧客管理）のブラウザ操作に対するE2Eテスト観点とテストケースをまとめたものです。

FeatureテストではHTTPリクエストとDB更新の主要な振る舞いを確認していますが、E2Eでは次のようなブラウザ上でしか発見しにくい不具合を重点的に確認します。

- サイドモーダル、CSVインポートモーダル、通常詳細画面の表示差分
- JavaScriptによるAjax保存、二重送信防止、未保存確認、スクロール制御
- 一覧の横スクロール、固定列、レスポンシブ表示
- 複数タブ操作、削除済みデータへの操作
- CSVインポート時の長いエラー表示、重複確認、成功通知

## 2. 影響範囲の分析

### 2.1 共通レイアウト・ナビゲーション

影響する主なファイル:

- `app/resources/views/components/layouts/app.blade.php`
- `app/resources/views/home.blade.php`
- `app/public/css/app.css`
- `app/public/js/app.js`

確認が必要な理由:

- オペナビ配下ではサイドバーを表示し、トップ画面では共通ナビゲーションを表示しない方針。
- サイドバーは開閉でき、狭い画面幅でも文字だけが消えるなどの表示崩れが起きやすい。
- 成功・失敗メッセージは画面や操作種別によって表示位置が異なる。

### 2.2 顧客一覧

影響する主なファイル:

- `app/resources/views/customers/index.blade.php`
- `app/app/Services/Opnavi/CustomerQueryService.php`
- `app/app/Http/Controllers/CustomerController.php`
- `app/public/css/app.css`
- `app/public/js/app.js`

確認が必要な理由:

- 検索、絞り込み、チップ、並び替え、表示件数、ページネーションが同時に作用する。
- 一覧順は詳細画面の「戻る」「次へ」にも影響する。
- 一覧上で担当者・次回アクション日を即保存する。
- 一括担当者設定、チェックボックス、固定列、横スクロールがある。

### 2.3 サイドモーダル詳細・通常詳細

影響する主なファイル:

- `app/resources/views/customers/_detail.blade.php`
- `app/resources/views/customers/show.blade.php`
- `app/public/js/app.js`
- `app/public/css/app.css`

確認が必要な理由:

- `_detail.blade.php` はサイドモーダルと通常詳細画面で共通利用している。
- サイドモーダルではAjax送信、通常詳細では通常フォーム送信になる。
- 保存成功メッセージの表示位置、未保存確認、前後移動、スクロール可否が表示形式ごとに異なる。

### 2.4 架電・対応履歴

影響する主なファイル:

- `app/resources/views/customers/_detail.blade.php`
- `app/app/Services/Opnavi/CustomerActivityService.php`
- `app/app/Http/Requests/ActivitySaveRequest.php`
- `app/public/js/app.js`

確認が必要な理由:

- 履歴登録時に顧客のステータス、最終アクション日、最終メモへ同期する。
- 履歴登録後の既存履歴はメモだけ更新できる仕様。
- 登録フォームの日時は詳細表示時に自動入力するが、その自動入力だけで未保存扱いにしてはいけない。
- サイドモーダルでは履歴登録成功メッセージを「架電・対応履歴」の上に表示する。

### 2.5 CSVインポート

影響する主なファイル:

- `app/resources/views/customers/index.blade.php`
- `app/app/Services/Opnavi/CustomerImportService.php`
- `app/app/Http/Requests/CustomerImportRequest.php`
- `app/public/js/app.js`
- `app/public/css/app.css`

確認が必要な理由:

- 必須列、必須値、空行スキップ、営業日数12日未満スキップ、重複確認、店舗数の取り込みがある。
- エラーが長い場合はモーダル内だけスクロールし、背景の一覧はスクロールしない必要がある。
- モーダルを閉じたらエラー表示と入力状態をリセットする必要がある。

### 2.6 複数タブ・削除済みデータ

影響する主なファイル:

- `app/routes/web.php`
- `app/app/Http/Controllers/CustomerController.php`
- `app/public/js/app.js`
- `app/resources/views/components/layouts/app.blade.php`

確認が必要な理由:

- 同じ顧客を複数タブで開く可能性がある。
- 仕様上、同時編集は「最後に保存した内容が反映される」方針。
- 一方で、別タブで論理削除された顧客への詳細表示・保存・履歴登録は成功させず、分かるエラーを表示する必要がある。

## 3. E2E前提データ

最低限、以下のデータを用意して実施します。

| 種別 | 内容 |
|---|---|
| 担当者 | 砂澤、荒 |
| 顧客A | サンプル体験株式会社。神奈川県、登録日が新しい、OTA複数、次回アクション日あり |
| 顧客B | 野口農園。埼玉県、登録日が顧客Aの次、未担当 |
| 顧客C | 長い事業者名の顧客。横スクロール・折り返し確認用 |
| 顧客D | 履歴あり。最新履歴ステータスが契約または失注 |
| CSV正常ファイル | 必須列あり、営業日数12日以上、店舗数あり、OTA_URLあり |
| CSVエラーファイル | 必須値不足、重複、長いエラー、空行、営業日数12日未満を含む |

## 4. 優先度

| 優先度 | 意味 |
|---|---|
| P0 | 保存・削除・CSV取込など、業務停止につながる重要ケース |
| P1 | 主要画面の導線、検索、履歴、サイドモーダルなど日常利用で頻度が高いケース |
| P2 | レスポンシブ、表示崩れ、補助導線など、品質担保として確認したいケース |

## 6. 自動E2E化する場合の推奨グループ

Playwrightなどで自動化する場合は、以下の順で分けると保守しやすいです。

| グループ | 含めるケース |
|---|---|
| `home-and-navigation.spec` | トップ、サイドバー、ダッシュボード遷移 |
| `customer-list.spec` | 検索、並び替え、チップ、ページネーション、横スクロール |
| `customer-inline-and-bulk.spec` | 一覧即保存、一括担当者設定 |
| `customer-drawer.spec` | サイドモーダル、未保存確認、コピー、前後移動 |
| `customer-detail.spec` | 通常詳細、削除、通常保存、スクロール |
| `activity.spec` | 履歴登録、ステータス同期、メモ更新 |
| `csv-import.spec` | 正常取込、エラー、重複、長いエラー、モーダルリセット |
| `multi-tab.spec` | 同時編集、削除済み顧客への操作 |
| `responsive.spec` | 主要画面の狭幅表示 |

## 7. 重点的に壊れやすい箇所

E2E実施時は、特に以下を優先して確認します。

1. サイドモーダルと通常詳細で、同じ保存処理が別の画面遷移になっていないか。
2. 成功メッセージが複数箇所に重複表示されないか。
3. 履歴登録後に顧客ステータスと一覧表示が同期しているか。
4. 一覧の検索条件と並び替え条件が、詳細の「戻る」「次へ」に引き継がれているか。
5. CSVインポートでエラーが長い場合、モーダル内スクロールになっているか。
6. bodyのスクロールロックが、通常詳細画面や別タブ詳細画面に残らないか。
7. ダブルクリックで重複登録、重複インポート、重複メッセージが起きないか。
8. 別タブで削除された顧客に対する保存・履歴登録が成功扱いにならないか。
9. 狭い画面幅で、コピーボタン、日付入力、履歴フォーム、サイドバーがはみ出さないか。
10. 一覧の固定列が横スクロール時に他列の文字を透過して見せないか。

## 8. 現時点のFeatureテストで確認済みの主な内容

| 項目 | 確認済み内容 |
|---|---|
| 一覧検索 | 都道府県・担当者の絞り込み |
| 一覧即保存 | 担当者変更後に一覧へ戻りDB更新される |
| 一括担当者設定 | 選択顧客のみ担当者を更新、未選択時はエラー |
| 詳細前後移動 | 現在の一覧ソート順に沿って前後顧客を判定 |
| 履歴登録 | 顧客ステータス、最終アクション日、最終メモへ同期 |
| 履歴更新 | 既存履歴のメモ更新 |
| CSVインポート | 顧客・OTAリンク作成、営業日数12日未満スキップ、空行スキップ、店舗数保存 |
| 複数タブ削除 | 削除済み顧客の詳細・更新・Ajax詳細取得でエラー扱い |

E2Eでは、上記のDBレベルの確認に加えて、実際の画面遷移、表示位置、スクロール、二重送信、レスポンシブ表示を確認します。
